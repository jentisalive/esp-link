# ESP Link

Локальный пульт для **uPesy ESP32 Wroom DevKit**: нативные приложения для iPhone/iPad (iOS 16+) и **Android 8+**, плюс прошивка ESP32.

**Android:** скачайте APK из Releases и установите на телефон. Инструкции и разрешения: [ANDROID.md](docs/ANDROID.md). Прошивка платы та же, что для iOS. **get_token.bat** открывает USB-монитор для просмотра токена без перепрошивки.

- **Bluetooth LE**: поиск платы в приложении, проверка токена, команды и ответы через GATT. Не Bluetooth Classic/SPP.
- **Wi-Fi**: плата создаёт сеть `ESP32-Link-XXXX`, роутер и интернет не нужны.
- `1` → **три мигания встроенного LED на GPIO 2**, затем подтверждение завершения.
- Также: `on`, `off`, `status`, `ping`; произвольный ввод команд, журнал последних 100 событий.
- Токен генерируется на плате, сохраняется в NVS и в Keychain приложения. Нет облака и сторонних SDK.
- GitHub Actions: тесты, unsigned IPA, приложение для симулятора и готовый образ прошивки. Отдельный ручной workflow для подписи Apple.

## Быстрый старт

### 1. Получить сборки

Опубликуйте проект в своём репозитории: [инструкция для GitHub](docs/GITHUB.md). Во вкладке **Actions → Build and test** дождитесь завершения обеих задач и скачайте:

- `ESPLink-uPesy-firmware` — образ платы и инструкция по прошивке;
- `ESPLink-iOS-unsigned` — `ESPLink-unsigned.ipa` и приложение для симулятора.

**Unsigned IPA нельзя установить на iPhone напрямую.** Его нужно подписать, например через Sideloadly на Windows или AltStore. При бесплатной личной подписи обычно требуется обновление каждые 7 дней; условия зависят от Apple и способа установки. Apple ID вводится только в выбранном инструменте подписи, **не в GitHub Secrets и не в этот проект**. Для workflow с сертификатами см. [подпись iOS](docs/IOS.md).

### 2. Прошить uPesy ESP32

Подключите плату USB-кабелем **с передачей данных**. Для готового образа следуйте [FLASH.txt](docs/FLASH.txt). Прошивка заменяет текущую программу платы — предварительно сохраните старую, если она нужна.

Либо соберите из исходников с Python и PlatformIO:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install platformio==6.1.18
.\.venv\Scripts\python.exe -m platformio run -d firmware -e upesy_wroom -t upload
.\.venv\Scripts\python.exe -m platformio device monitor -b 115200
```

Порт обычно определяется автоматически. Если нужно, добавьте `--upload-port COM5` при загрузке или `--port COM5` для монитора, подставив свой порт. Если нет связи — удерживайте BOOT при начале загрузки. Можно также открыть папку `firmware` в VS Code с расширением PlatformIO.

Откройте Serial Monitor на **115200**, нажмите **RESET**. В выводе будут:

```text
Device / Wi-Fi SSID: ESP32-Link-XXXX
Device token / Wi-Fi password: <12 hex-символов вашей платы>
HTTP address: http://192.168.4.1
```

Токен не меняется при обычном перезапуске. Полное стирание flash/NVS удалит его и другие данные платы. Не публикуйте вывод Serial с токеном.

### 3. Подключить iPhone

**Bluetooth:** введите токен → Bluetooth → «Найти ESP32» → выберите плату → «Мигнуть 3 раза». Сопряжение в системных настройках не требуется. Разрешите приложению доступ к Bluetooth.

**Wi-Fi:** в настройках iPhone выберите `ESP32-Link-XXXX`, пароль — тот же токен. Согласитесь остаться в сети без интернета. Вернитесь в приложение → Wi-Fi → адрес `192.168.4.1` → токен → подключиться. Разрешите доступ к локальной сети.

```text
flash_esp32.bat            Прошивка платы и необязательный USB-монитор
docs/                      Подпись iOS, GitHub, протокол, проверка на железе
```

## Разработка и ограничения

- Для локальной iOS-сборки нужен Mac с Xcode и XcodeGen: [IOS.md](docs/IOS.md). На Windows iOS собирается через macOS-runner GitHub Actions.
- BLE проверяется **на настоящем iPhone и плате**: симулятор не заменяет радиомодуль. Тесты CI проверяют логику, но не реальную радиосвязь.
- Прошивка настроена на `board = upesy_wroom`, ESP32 WROOM, 4 MB flash. Не прошивайте этим образом ESP32-C3/S2/S3.
- Активный HIGH светодиод — GPIO 2; изменение в `firmware/platformio.ini`. После мигания LED остаётся выключенным.
- Приложение работает на переднем плане. При уходе в фон соединение закрывается; уже принятая платой команда продолжит выполняться.
- Потеря ответа не означает, что команда не выполнилась. Автоматических повторов команд нет.
- Это прототип для своей платы в доверенной локальной среде. HTTP без TLS; BLE-токен передаётся без обязательного BLE-шифрования. Не используйте для замков, двигателей и других критичных механизмов. Подробности: [PROTOCOL.md](docs/PROTOCOL.md).

Проверка C++ логики на Linux/macOS с установленным C++ компилятором:

```sh
pio test -d firmware -e native
```

Чек-лист реального устройства: [TESTING.md](docs/TESTING.md).
