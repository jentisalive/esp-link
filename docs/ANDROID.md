# ESP Link для Android

## Установка

1. Откройте Releases приватного репозитория, войдя в GitHub.
2. Скачайте **ESPLink-android-v1.1.0.apk** на телефон (Android 8.0+).
3. Разрешите установку из этого источника в системном диалоге и установите APK. Google Play, Apple ID и самостоятельная подпись не нужны.
4. Откройте ESP Link. Введите 12-символьный токен из USB Serial Monitor платы.

Готовая прошивка ESP32 из v1.0.0 совместима — перепрошивать плату для Android не нужно. Тестовый скетч с другим BLE-сервисом не подходит.

## Получить токен без перепрошивки

В подготовленной папке проекта на Windows запустите **get_token.bat**, затем нажмите RESET / EN на плате. Монитор работает на 115200 baud и выводит строку `Device token / Wi-Fi password`. Батник ничего не прошивает, не стирает и не меняет токен. Закройте Serial Monitor Arduino IDE перед запуском.

Если порт не определился автоматически:

```cmd
get_token.bat COM5
```

Замените COM5 своим портом. Батнику нужна `.venv` с PlatformIO из проекта. На другом компьютере сначала выполните подготовку окружения из README. Сам APK не требует Python или компьютера.

## Bluetooth LE

- Включите Bluetooth, введите токен → «Найти ESP32» → выберите ESP32-Link-XXXX.
- Android 12+: разрешите доступ к устройствам поблизости (Bluetooth Scan/Connect).
- Android 8–11: поиск BLE требует разрешения геолокации и включённого системного переключателя геолокации. Приложение не получает координаты и никуда их не отправляет.
- Сопряжение через системные настройки и nRF Connect не нужны. Первый запуск может занять несколько секунд.
- После подключения нажмите «Мигнуть 3 раза». Доступны также on, off, status, ping.

## Wi-Fi

В настройках телефона подключитесь к ESP32-Link-XXXX; пароль сети совпадает с токеном. Выберите «Остаться в сети без интернета», если Android спросит. Вернитесь в приложение → Wi-Fi → `192.168.4.1` → токен → подключиться.

HTTP-запросы привязаны к Wi-Fi-сети, а не к мобильному интернету. Перенаправления HTTP запрещены; принимаются только частные IPv4-адреса и имена `.local`. Плата в базовой прошивке доступна по IP, автоматическое обнаружение по mDNS не реализовано.

## Сборка

Нативное Android-приложение на Java и Android SDK, без сторонних runtime-библиотек. minSdk 26, target/compile SDK 35. Для локальной сборки: Android Studio / JDK 17, Android SDK 35 и Build Tools 35.0.0.

```sh
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Windows: `gradlew.bat` вместо `./gradlew`. Для локального SDK можно создать `android/local.properties` с `sdk.dir=...`; файл не публикуется. Gradle Wrapper и дистрибутив закреплены контрольными суммами.

В GitHub Actions **Android APK** выполняются unit-тесты, Android Lint, debug-сборка и подписанная release-сборка. Дополнительно проверяются реальная подпись APK, package ID, версия, minSdk/targetSdk, Bluetooth-разрешения и отсутствие debuggable.

Release-подпись постоянная: PKCS12 alias `esplink`, секреты GitHub `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEYSTORE_PASSWORD`. Ключ и пароль не попадают в Git или исходный ZIP. Локальная резервная копия при первоначальной настройке находится в **.signing/**; сохраните её отдельно в безопасном месте. Не публикуйте и не пересылайте её. Потеря ключа не позволит подписывать обновления поверх установленной версии.

PR-сборки не получают ключ подписи и проверяют только debug-вариант. Подписанная сборка выполняется только на доверенной ветке main. Релизы этого проекта не являются публикацией в Google Play.

## Ограничения и ручная проверка

- Уход в фон закрывает сеанс и поиск. Уже принятая ESP32 команда продолжает выполняться. После возврата подключитесь заново.
- Автоматического повторения команд и автоподключения нет.
- Последний токен хранится в SharedPreferences только в зашифрованном AES-GCM виде; ключ — Android Keystore. Резервное копирование данных приложения отключено. После удаления приложения токен придётся ввести заново.
- Приложение работает с локальным HTTP без TLS и BLE без обязательного шифрованного pairing. Для своей платы в доверенной среде, не для опасных механизмов.
- Сборка и unit-тесты не заменяют проверку радио на настоящем Android-телефоне. Проверьте отказ/выдачу разрешений, поиск, неверный/верный токен, команды, потерю питания, Wi-Fi без интернета с включённым мобильным интернетом и переподключение.
