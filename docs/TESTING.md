# Проверка

## Автоматически

Workflow `Build and test`:

1. Генерирует Xcode-проект из `ios/project.yml`.
2. Выполняет XCTest в iPhone Simulator: валидация команд, токенов, локальных адресов, JSON-контракт; HTTP подключение/неверный токен/мигание/отсутствие автоматического повтора при busy через mock URLProtocol.
3. Собирает приложение для настоящего iPhone без подписи.
4. На Linux запускает C++ тесты `CommandEngine`: 3 импульса, занятость, команды, последовательные job, переполнение `millis()`.
5. Собирает firmware для `upesy_wroom`, формирует merged binary для flash с адреса `0x0`.

Успешная компиляция не подтверждает реальную радиосвязь. До завершения Actions iOS-сборка считается **непроверенной**.

## Ручной чек-лист: плата + настоящий iPhone

- [ ] Сохранить нужную старую прошивку; прошить именно uPesy ESP32 Wroom DevKit, не C3/S3.
- [ ] Serial 115200 + RESET: видны SSID, токен и IP; после второго RESET токен тот же.
- [ ] BLE: отказать в разрешении → понятное сообщение; разрешить в Settings → поиск работает.
- [ ] BLE: поиск без платы завершается примерно через 10 секунд, интерфейс не зависает.
- [ ] BLE: неверный токен → отказ; правильный → `ready`.
- [ ] `1`: три видимых импульса GPIO 2, журнал сначала «принята», потом «готово».
- [ ] `on`, `off`, `status`, `ping` корректны, неизвестная команда `2` не меняет LED.
- [ ] Отключить питание во время сеанса: приложение сообщает потерю связи; после включения можно подключиться заново.
- [ ] После разрыва BLE плата снова появляется в поиске; аутентификация запрашивается заново.
- [ ] Wi-Fi: выбрать SSID платы, пароль-токен; iPhone остаётся в сети без интернета.
- [ ] Разрешить локальную сеть; GET status и все команды доступны с адресом `192.168.4.1`.
- [ ] Wi-Fi: неверный токен → отказ; выход из сети → потеря связи за несколько секунд.
- [ ] Одновременно второй клиент: пока один запустил мигание, `1/on/off` другого возвращают busy.
- [ ] Уход приложения в фон закрывает сеанс; уже принятая плата завершает мигание. На возврате требуется подключение.
- [ ] Потерянный ответ не вызывает повторного запуска мигания сам по себе.
- [ ] В логах приложения нет токена, в репозитории нет сертификатов/паролей.

Если встроенный LED не мигает, проверьте маркировку платы и схему её ревизии. `done:1` подтверждает выполнение кода GPIO, но не исправность светодиода. Настройки пина: `firmware/platformio.ini`.
