# Публикация в GitHub

Файлы workflow уже в `.github/workflows/`. Они начнут работать только после загрузки проекта в GitHub. Локальная папка сама по себе не запускает Actions.

## Windows: новый приватный репозиторий

1. Установите Git и GitHub CLI, если их нет:

   ```powershell
   winget install --id Git.Git -e
   winget install --id GitHub.cli -e
   ```

2. Перезапустите PowerShell, откройте папку проекта и авторизуйтесь:

   ```powershell
   gh auth login
   gh auth setup-git
   git config --global user.name "Ваше имя"
   git config --global user.email "Ваш GitHub noreply email"
   ```

   Можно взять noreply email из GitHub → Settings → Emails. Эти команды настройки Git меняют глобальные параметры: пропустите их, если уже настроили свои.

3. Создайте **новый** приватный репозиторий, подставив аккаунт и имя:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\publish.ps1 -Repository YOUR_ACCOUNT/esp-link
   ```

   Скрипт не перезаписывает существующий `.git` и не удаляет файлы. Если публикация прервётся после создания коммита, продолжите вручную — повторный запуск намеренно остановится.

4. Откройте `https://github.com/YOUR_ACCOUNT/esp-link/actions` → **Build and test**. Workflow запускается на push в `main`, pull request или вручную (**Run workflow**). Артефакты доступны после успешной сборки, срок хранения — 14 дней.

## Уже существующий репозиторий

Сначала клонируйте нужный репозиторий, перенесите файлы проекта (без `.venv`, `.pio`, `dist`), проверьте `git diff` и сделайте commit/push. Не используйте принудительный push или перезапись существующих файлов без проверки. Если основной branch не `main`, исправьте список веток в `build.yml`.

## Без CLI

Можно создать репозиторий в браузере и загрузить исходники через **Add file → Upload files**, сохранив дерево папок. Обязательно загрузите скрытую папку **`.github`**. Нельзя загружать только ZIP: GitHub не распакует его в рабочие исходники и Actions не появятся.

`python scripts/package_source.py` создаёт `dist/ESPLink-source.zip` для переноса. Перед загрузкой распакуйте его. Подписные файлы, локальные инструменты и результаты сборок в архив не попадают.

## Стоимость и безопасность

- Бесплатная квота и доступность macOS-runner зависят от аккаунта и тарифного плана GitHub. Для приватных репозиториев проверьте **Settings → Billing / Actions**. macOS может расходовать квоту быстрее Linux.
- Обычная сборка не требует Apple-секретов; `GITHUB_TOKEN` имеет только `contents: read`.
- Workflow ручной подписи запускайте только на доверенной ветке. Не добавляйте сертификаты в репозиторий.
- После передачи файлов другому человеку проверьте содержимое архива и `git diff`. Токен платы, Apple ID и приватные ключи публиковать не нужно.
