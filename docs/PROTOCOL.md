# ESP Link 1.2.0 — Wi-Fi-only протокол

Плата: uPesy ESP32 Wroom DevKit, GPIO 2, LED active HIGH. **Bluetooth-контроллер остановлен, память BT освобождена до запуска Wi-Fi.** BLE/GATT/SPP, поиск и advertising отсутствуют.

## Wi-Fi и доступ

Точка доступа WPA2: `ESP32-Link-XXXX`, IP `192.168.4.1`, HTTP порт 80. Один подключённый Wi-Fi-клиент. Роутер/интернет не нужны. Wi-Fi пароль и токен управления независимы.

- При первом запуске/обновлении Wi-Fi-only прошивка создаёт случайный 20-символьный hex-пароль сети и сохраняет `wifi-pass` в NVS namespace `esp-link`.
- Существующий Device token из NVS сохраняется; при отсутствии создаётся случайный 12-символьный токен. Начиная с прошивки 1.2.4, собственный токен может иметь 8–64 латинских букв и цифр.
- После EN / RESET USB Serial 115200 выводит SSID, Device token и Wi-Fi password отдельными строками.
- Обычное выключение питания их не меняет. Полное стирание flash/NVS удаляет оба значения.

Каждый API-запрос требует `X-Device-Token: <Device token>`. Токен не передаётся в URL. Пароль Wi-Fi в API не отправляется.

### GET `/api/status`

```json
{"name":"ESP32-Link-1234","protocolVersion":1,"transport":"wifi-only","busy":false,"led":false,"completedJob":1}
```

### POST `/api/command`

`Content-Type: text/plain; charset=utf-8`. Тело — одна регистрозависимая команда, 1–20 печатных ASCII-байтов, без завершающего перевода строки. Приложение удаляет пробелы с краёв.

| Команда | JSON reply | Действие |
| --- | --- | --- |
| `1` | `accepted:1`, HTTP 202 + `job` | Три импульса LED по 250 мс, 250 мс паузы, затем LOW |
| `on` | `ok:on` | HIGH |
| `off` | `ok:off` | LOW |
| `status` | `status:on`, `status:off`, `status:blinking` | Статус |
| `ping` | `pong` | Проверка связи |
| `m1test` | `ok:m1test`, HTTP 202 | Один тест мотора A |
| `mtest` | `ok:mtest`, HTTP 202 | Один стендовый цикл A и B |
| `m1stop` | `ok:m1stop`, HTTP 200 | Запрос остановки всех моторов |

Пример: `{"reply":"accepted:1","job":1}`. Для завершения опрашивайте status до `completedJob >= job`. Счётчик сбрасывается после перезапуска. Это подтверждение кода GPIO, не оптическая проверка светодиода.

Во время мигания `1/on/off` возвращают HTTP 409 `error:busy`; status/ping доступны. HTTP 400 — неправильная команда; 401 — неверный токен; 404 — неизвестный путь. CORS не включён. Автоматического повтора POST нет: потерянный ответ не доказывает, что команда не выполнилась.

Пока моторный тест идёт или останавливается, оба запуска возвращают HTTP 409 `error:m1-busy`; при недоступности моторного теста — HTTP 503 `error:m1-unavailable`. У моторных тестов нет `job`: ответ подтверждает приём команды, а не движение вала.

## Пульт (прошивка ≥ 1.3.0)

Запросы требуют тот же `X-Device-Token` и не повторяются автоматически. `GET /api/remote` возвращает `version: 1`, `motors`, `bucket`, `mv` (0 означает нет данных) и `low`.

`POST /api/remote/arm` открывает один захват и возвращает `id`, сам не включает тягу. `POST /api/remote/frame` принимает `id,seq,x,y,bucket`, где `seq` строго возрастает, оси от −100 до 100, `bucket` — 0 либо однократное переключение. Тайм-аут между принятыми кадрами — 250 мс. Просроченный захват не восстанавливается. `m1stop` аннулирует захват и снимает тягу. Стендовые циклы и пульт не работают одновременно. Правильный ответ не подтверждает физическое движение.

## Смена Wi-Fi пароля — только USB

Serial 115200, ASCII, строки завершаются LF. Максимальный frame — 95 символов; непечатные/слишком длинные/незавершённые frames отбрасываются. Введённый пароль не эхируется.

1. `esplink:hello` → `ESPLINK:WIFI-ONLY:1` (проверка совместимости перед передачей секрета).
2. `esplink:wifi-password:<новый пароль>` → `ESPLINK:PASSWORD-SAVED` после успешной записи NVS.
3. Точка доступа перезапускается и отключает текущего клиента. Device token не меняется.

Пароль: 8–63 ASCII-символа с кодами 33–126, без пробелов. Рекомендуется случайный пароль 16+ символов. Ошибки: `ESPLINK:ERROR:PASSWORD`, `ESPLINK:ERROR:NVS`, `ESPLINK:ERROR:FRAME`, `ESPLINK:ERROR:COMMAND`. Если ACK потерян, состояние неопределённо: пароль мог сохраниться. Не повторять автоматически, проверить через EN и USB-монитор.

`esplink:info` выводит SSID, токен и пароль по USB, как после RESET. Скрипт `change_wifi_password.bat` / `scripts/change_wifi_password.py` проверяет handshake, скрыто запрашивает пароль дважды и ждёт ACK. Пароль не поддерживается в аргументах командной строки. В HTTP нет endpoint смены пароля.

## Границы защиты для робота

Bluetooth выключен, но Wi-Fi не становится неуязвимым: остаются радиопомехи, глушение/deauth и перегрузка локального HTTP-клиентом с доступом к сети. Один клиент — ограничение числа станций, не анти-DoS-гарантия. HTTP без TLS, NVS без шифрования; доступ к USB даёт доступ к настройкам. Не раскрывайте Wi-Fi пароль или токен.

Моторные команды предназначены для ограниченного по времени стендового теста. Перед эксплуатацией робота нужны аппаратный аварийный стоп, watchdog команд и проверка допустимых состояний исполнительных механизмов. Безопасность робота нельзя возлагать на доступность Wi-Fi.
